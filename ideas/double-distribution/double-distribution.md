# Идея: Double Distribution

## 1. Краткое описание

Double Distribution — система распространения машин и других возможностей проекта Double через плагины и навыки для различных AI-агентов. Единые исходники Double преобразуются в устанавливаемые пакеты, соответствующие требованиям конкретных агентов и площадок.

Пользователь применяет машины Double в привычном интерфейсе своего агента, включая мобильные сценарии там, где среда предоставляет необходимые инструменты.

## 2. Контекст возникновения

Идея возникла при обсуждении интеграции Double с Codex, ChatGPT, Claude, Kimi и другими AI-агентами, доступными через графические и мобильные интерфейсы.

Проект уже содержит машины, workflow, роли, инструкции, шаблоны и навыки. Их наличие в рабочем репозитории ещё не обеспечивает простую установку и использование за его пределами. Различные агенты используют близкие, но не полностью совместимые форматы плагинов. Дополнительно существуют официальные каталоги поставщиков и независимые площадки распространения.

Необходимо превратить возможности Double в доступную пользователю поставку, сохранив единый источник содержания машин. Дополнительного денежного бюджета на проект сейчас нет, поэтому бесплатные каналы имеют приоритет.

## 3. Проблема и мотивация

Пользователь не должен вручную разбирать устройство репозитория Double, копировать внутренние файлы и исправлять зависимости между ними. Автор проекта не должен поддерживать расходящиеся копии каждой машины под каждого агента.

Система распространения должна обеспечивать:

- понятную установку и обновление;
- сохранение процессов и контрактов машин;
- воспроизводимую сборку пакетов;
- доступность бесплатных каналов;
- возможность расширять поддержку агентов и площадок.

## 4. Исходное описание

Double сохраняет единые исходники машин и получает слой упаковки и распространения. Этот слой определяет состав выпуска, выбирает версии компонентов, включает необходимые зависимости и формирует пакеты для поддерживаемых агентов. Один выпуск плагина может объединять несколько машин, версии которых развиваются независимо.

Предусматриваются два способа доставки:

1. Через GitHub: готовые устанавливаемые папки, собственные каталоги плагинов и релизные архивы.
2. Через внешние площадки: официальные каталоги поставщиков и независимые каталоги, индексирующие или принимающие пакеты Double.

Папка пакета в GitHub и релизный архив могут быть разными формами поставки одного выпуска. Публикация, проверка и доступность новой версии учитываются отдельно для каждой площадки.

### Общие принципы, обсуждённые при формулировке идеи

Это положения исходного обсуждения, а не отдельный результат этапа синтеза принципов:

1. **Единый источник содержания.** Машины, workflow и шаблоны развиваются в Double; платформенные пакеты формируются из этих исходников.
2. **Адаптация упаковки.** Различия агентов отражаются прежде всего в манифестах, настройках инструментов и способах установки.
3. **Полнота поставки.** Установленный компонент получает все необходимые материалы и не зависит от отсутствующих файлов исходного репозитория.
4. **Независимость версий.** Версия плагина и версии включённых машин фиксируются отдельно.
5. **Разделение содержания и пользовательских данных.** Пакет содержит процессы и шаблоны; идеи, цели и знания пользователя сохраняются в выбранном рабочем пространстве.
6. **Проверяемая совместимость.** Поддержка агента, десктопного или мобильного интерфейса заявляется после проверки соответствующего сценария.
7. **Приоритет бесплатного распространения.** При текущем нулевом бюджете используются каналы без обязательных дополнительных расходов.
8. **Явный учёт затрат.** Плата за публикацию, подписка агента, продвижение и выполнение запросов рассматриваются как разные виды затрат.

### Площадки-кандидаты

| Группа | Площадки | Назначение |
| --- | --- | --- |
| Основной источник | GitHub | Исходники, устанавливаемые пакеты, версии и релизные файлы |
| Официальные каталоги | OpenAI, Claude, Cursor, Kimi | Распространение внутри экосистем поставщиков с их процедурами проверки |
| Независимые каталоги плагинов | HOL, Claude Marketplaces | Обнаружение Double и переход к подходящему способу установки |
| Каталоги навыков | skills.sh, SkillsMP, MCP Market, SkillsLLM | Распространение и обнаружение отдельных машин и навыков |
| Дополнительные экосистемы | ClawHub | Распространение после проверки формата и совместимости лицензии |

Перечень представляет кандидатов. Включение в него не подтверждает совместимость, бесплатность всех функций или обязательство публиковаться на каждой площадке. Независимый каталог не заменяет официальный каталог мобильного ChatGPT и сам по себе не предоставляет облачное исполнение.

### Бесплатные каналы и каналы с расходами

**Бесплатный способ:** публичный репозиторий, установка из GitHub, бесплатная индексация или подача в каталог без обязательной дополнительной оплаты издателем.

**Способ с расходами:** канал требует платной подписки издателя, платного размещения либо выбранного продвижения. Он используется после отдельного согласования бюджета. Наличие платных функций у площадки не исключает её бесплатный канал.

Стоимость установки и использования для пользователя рассматривается отдельно: бесплатное распространение пакета не означает бесплатность выбранного AI-агента, запросов к модели или внешних сервисов. Продажа самого Double остаётся отдельным неуточнённым вопросом.

## 5. Ключевые элементы

- Единые исходники машин Double и их операционных материалов.
- Навыки машин и устанавливаемый плагин Double.
- Состав выпуска и точные версии включённых компонентов.
- Workflow сборки и проверки платформенных пакетов.
- GitHub как источник пакетов и возможное хранилище пользовательских артефактов.
- GitHub MCP как рассматриваемая облачная интеграция без собственного MCP-сервера Double.
- Рабочее пространство пользователя: репозиторий, ветка, корневая папка и способ сохранения.
- Бесплатные каналы и каналы с дополнительными расходами.
- Отдельные состояния сборки, публикации в GitHub, внешнего review и появления в каталоге.

## 6. Допущения

- Существенная часть содержания машин может оставаться общей для нескольких агентов.
- Форматы пакетов и условия площадок допускают автоматизированную подготовку хотя бы части поставок.
- Для бесплатного старта достаточно публичного GitHub и выбранных независимых каталогов; это предположение предстоит проверить на первом выпуске.
- Возможность чтения и записи через GitHub MCP зависит от клиента, авторизации и разрешений и не считается подтверждённой для всех мобильных агентов.
- Публикация в стороннем каталоге не означает одобрение поставщиком агента.
- Условия площадок, цены и доступность функций меняются; сведения об условиях требуют проверки перед подачей.

## 7. Примеры и сценарии

### Установка

Пользователь находит Double в каталоге, выбирает вариант для своего агента и устанавливает пакет по инструкции. Материалы машин доступны без ручного восстановления структуры исходного репозитория.

### Расширение состава

Пример начального состава — Машина идей и Double Agent. Позднее выпускается новая версия с Машиной знаний или Машиной целей, без ручного переноса предыдущих компонентов. Этот пример не фиксирует обязательный состав первого выпуска.

### Мобильная работа

Пользователь выбирает рабочий GitHub-репозиторий, обсуждает идею в мобильном интерфейсе агента и сохраняет результат через доступное облачное подключение. В новом разговоре он читает сохранённый артефакт и продолжает работу при выключенном компьютере.

На текущем этапе рассматривается GitHub MCP без собственного MCP-сервера Double. Сценарий должен быть подтверждён для конкретного клиента; сохранение результата не предполагает хранения состояния только в истории чата.

## 8. Признаки ценности

- Снижается порог входа для пользователей Double.
- Машины доступны через уже используемые агентские среды.
- Сопровождение общих процессов отделено от платформенной упаковки.
- Новые машины можно включать в поставку без создания отдельного продукта для каждого агента.
- Бесплатные каналы позволяют начать распространение при нулевом дополнительном бюджете.
- Мобильный доступ позволяет работать с идеями, целями и знаниями вне рабочего компьютера.

## 10. Границы и нецели

- Создание собственного AI-агента или собственной модели не предусматривается.
- Отдельная реализация каждой машины под каждого поставщика не является желаемым способом сопровождения.
- Собственный MCP-сервер Double на текущем этапе не создаётся.
- Обязательные расходы и гарантированное присутствие во всех официальных каталогах не предполагаются.
- Конкретная структура каталогов сборки и реализация workflow остаются предметом последующего планирования.
