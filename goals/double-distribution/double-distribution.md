# Цель: готовность Double к распространению

## 1. Краткое описание

Проект Double находится в состоянии, позволяющем воспроизводимо собирать, проверять, выпускать и обновлять устанавливаемые плагины и навыки для согласованных AI-агентов, распространять их через бесплатные каналы и использовать подготовленные процедуры для каналов, требующих расходов.

Это черновик формулировки цели. Связанная идея: [Double Distribution](../../ideas/double-distribution/double-distribution.md#double-distribution).

## 2. Субъект цели

### Субъект

- Проект Double и его распространяемые машины.
- Система упаковки, проверки, выпуска и сопровождения плагинов и навыков Double.

Владелец цели — проект Double (`project-id: double`, `owner-id: densclub`).

## 3. Мотивация

Пользователи должны устанавливать возможности Double без ручного восстановления внутренней структуры проекта. Сопровождающие должны выпускать новые версии без поддержки расходящихся копий машин.

Достижение цели обеспечивает бесплатный старт распространения, расширение поддерживаемых агентских сред и подготовку к использованию каналов с расходами после согласования бюджета.

## 4. Текущее состояние

### Известные факты

- Исходники машин и их операционные материалы находятся в `.double/`.
- Существуют локальные точки входа для AI-агентов в `.agents/skills/`.
- Реализованы сборка и публикация релизных пакетов отдельных машин.
- Обсуждены платформы, каталоги и возможные способы распространения.
- Отдельный слой сборки устанавливаемых плагинов для выбранных каналов ещё не создан.
- Совместимость полного мобильного сценария с GitHub MCP ещё не подтверждена.
- Дополнительный денежный бюджет на проект отсутствует.

Существующие связанные поверхности: [каталог Double](../../.double/README.md), [инструменты сопровождения](../../scripts/scripts.md), [сборщик машин](../../scripts/double-release/double-release.py), [workflow релизов машин](../../.github/workflows/release.yml).

### Рабочая среда

GitHub-репозиторий Double, локальная среда подготовки пакетов, CI, официальные каталоги поставщиков и независимые площадки. Среда пользователя может быть десктопной или мобильной; её фактические инструменты и разрешения определяют доступные сценарии.

- [GitHub Actions Maintenance](../double-github-integration/github-actions-maintenance/github-actions-maintenance.md#github-actions-maintenance) — `direct-reference`; проект Double; существующий контекст релизной автоматизации. Связь не означает, что текущая цель уже включена в соответствующий план.

## 5. Целевое состояние

### Обязательный результат

В проекте определены и доступны:

- согласованный состав первого плагина и перечень поддерживаемых агентов;
- единый источник содержания машин;
- описание состава выпуска с точными версиями компонентов;
- воспроизводимый workflow сборки платформенных пакетов;
- готовые папки для установки из GitHub и необходимые релизные архивы;
- проверки структуры, зависимостей и пользовательских сценариев;
- инструкции установки, настройки, обновления и устранения проблем;
- правила публикации и обновления для выбранных площадок;
- учёт затрат, разрешений, лицензий и состояния внешних проверок.

Пользовательские артефакты сохраняются отдельно от установленного пакета. Для выбранного мобильного клиента подтверждена работа с облачным репозиторием без включённого компьютера пользователя и без собственного MCP-сервера Double.

### Возможные улучшения качества

Расширение списка агентов, увеличение числа каналов распространения и автоматизация дополнительных операций публикации возможны после определения обязательного объёма первого результата.

### Подтверждения целевого состояния

Релизные пакеты, описание их состава, результаты проверок чистой установки и обновления, публичные инструкции, ссылки на выбранные каналы распространения и результаты проверки мобильного сценария.

## 6. Критерии достижения

Критерии ниже перенесены из обсуждённого черновика. Конкретные агенты, каналы и состав первого выпуска остаются предметом уточнения в разделе 9.

| Критерий | Проверяемое подтверждение |
| --- | --- |
| Зафиксированы состав и версии компонентов | По выпуску можно однозначно определить включённые машины и точные исходники |
| Сборка воспроизводима | Повторная сборка из тех же входных данных даёт эквивалентное содержимое пакетов |
| Поставка самодостаточна | Установка в чистой среде не требует файлов рабочего checkout Double |
| Поддерживаются согласованные агенты | Основные сценарии проверены для каждого заявленного варианта |
| Работает бесплатное распространение | Пакет доступен по постоянной публичной ссылке и устанавливается по инструкции |
| Работает обновление | Проверен переход между двумя версиями без потери пользовательских артефактов |
| Подтверждён мобильный сценарий | С телефона создан и сохранён артефакт, затем прочитан в новом разговоре при выключённом компьютере |
| Подготовлены каналы с расходами | Описаны требования, материалы, стоимость и порядок подачи; фактическая оплата не обязательна |
| Разделены состояния выпуска | Сборка, выпуск в GitHub, отправка на review и публикация в каталоге учитываются раздельно |

**Минимальный успех:** выполнены критерии для согласованного обязательного набора компонентов, агентов и каналов, включая выбранный мобильный сценарий. Этот набор ещё не определён окончательно.

**Качественное расширение:** подтверждена работа дополнительных агентов и каналов без расхождения содержания машин.

**Частичный результат:** пакеты работают в десктопных средах, но мобильная работа или обновление ещё не подтверждены.

**Цель не достигнута:** доступны только исходники или архивы, требующие ручной доработки после установки, либо обязательные критерии не подтверждены.

## 7. Ограничения

- **Время:** срок достижения пока не установлен.
- **Внимание:** отдельный лимит не установлен; подготовка пакетов не должна требовать ручного сопровождения копий одних и тех же машин.
- **Стоимость:** текущая реализация не требует дополнительных денежных расходов. Платные действия возможны только после отдельного согласования. Стоимость канала для издателя отделена от стоимости использования агента пользователем.
- **Технические условия:** сохраняется единый источник машин; пользовательские данные не включаются в публичные пакеты; секреты не помещаются в исходники и релизы.
- **Интеграции:** на текущем этапе используется GitHub MCP. Собственный MCP-сервер Double не создаётся. Совместимость проверяется отдельно для каждого клиента.
- **Правовые и организационные условия:** лицензия должна допускать выбранные поставки; учитываются правила каталогов и права на публикуемые материалы.
- **Внешние решения:** одобрение и сроки review площадок не находятся под полным контролем проекта.

Готовность к платному каналу означает наличие подходящего пакета и процедуры подачи, а не уже понесённые расходы.

## 8. Ресурсы

### Доступные ресурсы

- Рабочий репозиторий Double и существующие машины.
- Действующие инструменты релизов машин и GitHub Actions.
- GitHub как источник версий, пакетов и документации.
- Обсуждённые площадки и их публичная документация, собранные в [идее Double Distribution](../../ideas/double-distribution/double-distribution.md#double-distribution).

### Недостающие или неподтверждённые ресурсы

- Согласованный обязательный состав первого выпуска и матрица поддержки.
- Подтверждённый доступ выбранного мобильного клиента к нужным операциям GitHub MCP.
- Выбранная лицензия распространяемых компонентов.
- Назначенный ответственный за выпуски и сопровождение публикаций.
- Согласованный бюджет для действий, требующих расходов; сейчас отсутствует.

## 10. Границы и нецели

В цель не входят:

- обязательная покупка подписок или продвижения;
- гарантированное одобрение всеми поставщиками;
- обязательная публикация на всех найденных площадках;
- создание собственного агента или облачной платформы исполнения;
- создание собственного MCP-сервера Double;
- реализация коммерческой продажи Double.

Конкретные пути, расположение сборочных каталогов и последовательность реализации не фиксируются этим артефактом: они относятся к последующим этапам после уточнения цели.
